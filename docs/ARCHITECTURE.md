# Архитектура Tendr

## Принципы

1. **Бэкенд — единственный источник бизнес-логики.** Бот и веб — тонкие клиенты.
2. **LLM за абстракцией.** Сейчас Mistral, завтра alemLLM — без изменений в коде агентов.
3. **RAG-индекс по доменам.** Закон, шаблоны заявок, реестр ТЗ — отдельные коллекции Qdrant.
4. **Маленькие специализированные агенты.** Каждый — отдельный класс со своим системным промптом.
5. **Freemium на уровне оркестратора.** Счётчик заявок, лимит по ролям.

## Агенты

### Documenter Agent
- **Вход:** текст ТЗ лота.
- **Выход:** `LotAnalysis` (название, заказчик, бюджет, требования, документы, красные флаги, summary).
- **Когда вызывается:** всегда при анализе лота.

### Legal Agent
- **Вход:** текст ТЗ + RAG по Закону РК.
- **Выход:** `LegalCheckResult` (пункты проверки, общий риск, черновик жалобы).
- **Когда вызывается:** по умолчанию вместе с Documenter.

### B2G Agent (в плане)
- Помощь заказчику: проверка ТЗ на дискриминацию, прогноз цены, шаблоны контрактов.

## Смена LLM-провайдера

Провайдеры: `Mistral` (основной) + `allemLLM` (через qwen3-6, резервный).

```bash
# Основной — Mistral
LLM_PROVIDER=mistral
LLM_API_KEY=...
LLM_BASE_URL=https://api.mistral.ai/v1
LLM_MODEL=mistral-large-latest

# Резервный — alemLLM через qwen3-6
# (когда Mistral недоступен, FailoverProvider переключится автоматически)
LLM_API_KEY_FALLBACK=sk-...
ALEM_BASE_URL=https://llm.alem.ai/v1
ALEM_MODEL=qwen3-6
```

`FailoverProvider` оборачивает primary + secondary. После 3 ошибок primary
переключается на secondary. Восстановление — при первом успешном вызове.

Особенности:
- alemLLM (`astanahub/alemllm`) сейчас часто возвращает 500, поэтому не основной.
- `qwen3-6` отключает thinking mode через `chat_template_kwargs: {enable_thinking: False}`.
- `mistral-embed` (dim=1024) — для RAG, alemLLM эмбеддинги не поддерживает.
