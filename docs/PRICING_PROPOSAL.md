## Правило использования

- Месячного бюджета анализов и пользовательских кредитов больше нет. Месячная цена — стоимость подписки, а не период сброса AI-лимита.
- Окно фиксированное: начинается при первом успешном резервировании и заканчивается через пять часов в UTC. Затем доступен весь лимит; следующее резервирование начинает новое окно. Это не скользящее восстановление по одному запуску.
- Успешный AI-разбор, AI-чат, глубокий поиск, подготовка AI-черновика и действия агента поставщиков резервируют по одному запуску. Пакетная AI-проверка лотов резервирует количество выбранных лотов и подтверждает фактическое число обработанных. Активные резервы уменьшают доступный остаток.
- Ошибка/неполный анализ освобождает резерв, но не переносит время обновления окна. Поздняя фиксация результата старого окна не списывается из нового.
- Поиск публичного каталога, просмотр истории и сохранённых результатов, сравнение уже сохранённых анализов и локальная сборка DOCX без нового AI-вызова не расходуют AI-лимит.
- В кабинете видны использованные анализы, выполняющиеся задания, остаток и время полного обновления. Данные квоты обновляются каждые 30 секунд.
- Тарифные возможности проверяются сервером. Plus не запускает функции Pro/Ultra; Pro не запускает поиск/черновики/внешние действия агента поставщиков. Бесплатный пробный доступ позволяет ознакомиться с функциями в пределах общего окна из трёх запусков.
- Сравнение 2–4 сохранённых лотов доступно в истории для Pro и Ultra: название, заказчик, бюджет, риск, число требований и красных флагов. Чужие анализы не доступны через этот endpoint.

## Оплата и совместимость

Покупка активируется только после подписанного Stripe webhook. Checkout предварительно проверяет Price ID: валюту KZT, точную цену в минимальных единицах, месячный период и active=true. Старый Price ID с прежней ценой блокирует создание оплаты с BILLING_PRICE_MISMATCH. Создать/выбрать новые Price ID нужно в Stripe; реальные платежи в этой среде не выполнялись.

Миграция `d02a13c004` добавляет начало окна в User и связь резерва с окном. История, платежи и старый ledger сохраняются. Старые записи без привязки к новому окну не уменьшают новое пятичасовое ограничение. Исторический Subscription.monthly_limit оставлен в БД для совместимости, но больше не управляет квотой. Legacy plan monthly сопоставлен ограничениям Pro. В API monthly_limit возвращается null; limit/used/remaining относятся к пятичасовому окну.

Подписка истекает по существующей дате expires_at; смена плана сама по себе не сбрасывает текущее окно. Административный сброс сохраняет результаты и журнал корректировок.
