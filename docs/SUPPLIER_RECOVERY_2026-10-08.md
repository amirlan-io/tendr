# Повторный поиск после проверки карточек — 8 октября 2026

Изменения локальные; GitHub, push, коммиты и отправка сообщений поставщикам не использовались.

## Что исправлено

- При достаточном лимите после первоначальных запросов каждой позиции остаётся одна попытка для поиска после сверки карточек. Локальный общий лимит остаётся 4, включая неудачные попытки.
- Решение о завершении позиции опирается на соответствие требованиям и подтверждённую цену, а не на название в поисковой выдаче. Общий бюджет по-прежнему требует количества для каждой позиции; доставка отдельно не подтверждена.
- Среди одинаково незавершённых позиций приоритет получает та, на которую потрачено меньше запросов. Повторный поиск выходит за список маркетплейсов; технические требования при сверке не ослабляются.
- Новые ссылки читаются и проверяются один раз. Дубли с завершающим слешем, заблокированные поставщики и совпадения только по одному слову в открытом поиске не запускают повторные проверки.
- Песочница использует общий конвейер проверки и повторного поиска. Лимит отображения не останавливает проверку остальных позиций; список резервирует место для лучшего предложения каждой позиции. Подтверждённая цена предпочтительнее отсутствующей при одинаковом соответствии.
- В интерфейсе показана причина незавершённой проверки: товар не найден, характеристики не подтверждены, отсутствует цена или превышен бюджет. Эти сведения относятся к найденным товарам до пользовательских фильтров.

## Проверки

Контролируемые тесты без внешних вызовов воспроизводят ошибочную первую карточку: фильтр найден, регулятор не соответствует ТЗ. После исправления третий запрос ищет регулятор и добавляет подтверждённый товар; расчёт комплекта становится 1 100 ₸. Поиск, чтение страницы и ответы модели в этом тесте имитируются — это доказательство логики восстановления, не качества модели или наличия реального товара. При ошибке поискового сервиса лимит остаётся соблюдён, комплект остаётся неполным.

Отдельно проверены отсутствие повторных LLM-вызовов, экономия запросов для уже закрытой позиции, стоп-лист, дубли ссылок, выбор недостаточно исследованной позиции, сохранение разных товаров в коротком списке и исключение финансовых новостей из поиска промышленного регулятора.

Полная серверная проверка после всех исправлений: **501 тест пройден**, 12 прежних предупреждений об устаревающем `datetime.utcnow()`. Тест интерфейса пройден, production-сборка пройдена. Vite сообщает о крупном JS-файле; это не ошибка сборки. `git diff --check` пройден.

## Живые результаты и ограничения

1. [Полный прогон](supplier-recovery-live-2026-10-08.json): 116 секунд, 4 базовых попытки Tavily, 5 LLM-вызовов, 8 прочитанных страниц. Оставлен 1 частично подтверждённый кандидат, комплект и бюджет не подтверждены. Прогон выявил выбор первой позиции при равенстве статусов и ограничение повторного поиска маркетплейсами; эти ошибки затем исправлены.
2. [Один дополнительный запрос](supplier-recovery-followup-2026-10-08.json): 30 секунд. На сохранённых решениях предыдущего прогона проверен исправленный выбор регулятора и открытый поиск. Найдена карточка Lunda: цена 804 344 ₸, DN80, фланец, но серый чугун и 16 бар вместо стали и 60,3 МПа. Агент отклонил её. Это отдельный дополнительный тест, не повторный полный прогон с тем же лимитом. Скрипт содержит фиксированные счётчики исходного сценария и предназначен именно для этого отчёта.
3. Открытый поиск также вернул финансовую новость со словом «регулятор». После этого добавлен фильтр совпадения полного наименования и регрессионный тест. Повторные платные вызовы после этого не делались.
4. Ноутбук недоступен: SSH к 192.168.1.183 возвращает `No route to host`. Успешных браузерных чтений на ноутбуке в этом прогоне нет; работу с ним не удалось перепроверить.

Общий расход проверки — **5 попыток Tavily**, облачный Browser-Use не использовался. Стоимость в JSON — приблизительная оценка кода, не выписка провайдера.

Оценка полного результата остаётся **6/10**: ошибки управления поиском исправлены, но полный комплект в живом тесте не получен. Отдельную новую оценку модели этот эксперимент не обосновывает. Текущие препятствия — отсутствие подтверждённого предложения для точного ТЗ и недоступность браузера на ноутбуке; одной замены модели или промпта для гарантированного результата недостаточно.
