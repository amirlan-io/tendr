# Интеграция исправленного архива

Основная версия — `amirlan-io/tendr`, commit `0d37db903d6bf2e9236cc631ed81e36c048e0969`.
PR [№3](https://github.com/amirlan-io/tendr/pull/3) с агентом поиска поставщиков уже входит
в эту версию: commit его ветки `4e12eff13d7219d9897bd0dbf554036d97fbe71b` является предком HEAD.
Сохраняются агент поставщиков, одобрения исходящих действий, Supabase, Stripe,
SSH-браузер, задания анализа в Redis и текущий веб-интерфейс.

Из загруженного `tendr-fixed.zip` перенесены совместимые исправления:

- Скрипты запуска используют пути проекта и `.venv`; встроенные ключи и пути чужой машины удалены.
- API запускается без LLM-ключа. `/api/health/live` проверяет жизнеспособность,
  `/api/health` сообщает о недоступных интеграциях.
- PDF/DOCX читаются вне цикла событий. Пустые, повреждённые и слишком большие документы,
  PDF и Excel сверх лимитов отклоняются вместо анализа сообщения об ошибке или обрезанного файла.
- Объявлены зависимости Excel и Mistral OCR. Для OCR используется отдельный ключ
  `MISTRAL_OCR_API_KEY` либо ключ основного Mistral; ключ другого провайдера не отправляется в Mistral.
- У загрузок уникальные ID. Последняя разрешённая операция не отклоняется повторной проверкой квоты.
- Разделы ТЗ перекрываются; повторные требования из перекрытия удаляются с сохранением
  количества, единиц и источника. Раздел источника сохраняется в результате и DOCX.
- После cooldown основной LLM снова проверяется. Немедленный fallback из main сохранён.
- RAG использует стабильные UUID, query-префикс локального E5 и проверяет размерность коллекции.
- Правовые выводы требуют актуальной отметки проверки корпуса, проверенных источников
  с HTTPS-ссылкой и редакцией, а также дословных цитат. Неподтверждённые выводы отклоняются.
- Каталог не присваивает вымышленный рейтинг пригодности лота без профиля компании.
- Тесты чтения страниц используют контролируемые DNS-ответы; SSRF-проверки частных,
  смешанных, пустых и неразрешимых DNS-ответов сохранены и расширены.

## Разрешение расхождений

Архив основан на более ранней структуре проекта. Его cookie-сессии/Telegram-вход
не заменяют действующую авторизацию Supabase. Изменённые старые миграции и ветка
миграций серверных сессий не переносятся: существующие базы должны сохранять
одну цепочку миграций. Tailwind 3, текущие зависимости интерфейса, тесты и
get_assistant_llm сохраняются. Готовые web/dist, архивные lock-файлы и отчёт
о старых тестах не используются как доказательство работоспособности общего кода.

## Запуск

Из корня проекта после установки зависимостей и запуска инфраструктуры:

```bash
bash scripts/start_api.sh
bash scripts/start_web.sh
# При настроенном Telegram:
bash scripts/start_bot.sh
```

Скрипт API по умолчанию слушает 127.0.0.1:8000; для другого порта задайте
`TENDR_API_PORT`. Прокси Vite рассчитан на API на порту 8000.
Для юридического корпуса разместите `corpus.json` рядом с документами:

```json
{
  "law.txt": {
    "verified": true,
    "official_url": "https://adilet.zan.kz/…",
    "version": "YYYY-MM-DD"
  }
}
```

Внесите реальную официальную ссылку и редакцию после проверки источника.
После индексации укажите `LEGAL_CORPUS_VERIFIED=true` и дату проверки
в `LEGAL_CORPUS_REVIEWED_AT`; по умолчанию срок актуальности — 90 дней.
Из-за смены ID и проверки размерности старые коллекции RAG требуют плановой
переиндексации. Интеграция не удаляет и не пересоздаёт существующие коллекции.

Изменения подготовлены в рабочей копии; автоматическая публикация на GitHub не выполнялась.
