# ТЗ: Автономный поиск поставщиков + персонализация Tendr

**Версия:** 1.0 (черновик для обсуждения)
**Охват:** всё, начиная с диалога про OpenClaw-агентов: поиск поставщиков по тендеру, письма/звонки с approval, политика торга, персонализация пользователя и тендеров, модели, экономика, ответ конкуренту ETS-Тендер.
**Вне охвата:** fully-autonomous звонки без одобрения (этап 6, только после статистики), ЭЦП-подписание, своя торговая площадка.

---

## 1. Цель и контекст

Tendr помогает МСБ **выигрывать** тендеры (слой победы), а не проводить торги. Новая фича: по тендеру и его требованиям агент находит в интернете компании с подходящим продуктом, сверяет по пунктам ТЗ, показывает шорт-лист, а связывается (письмо/звонок) **только после одобрения пользователя**.

Почему так, а не «полный автопилот»:
- агент может ошибиться в характеристике, цене, контрагенте;
- платные звонки без контроля = неконтролируемые расходы;
- Закон РК «О персональных данных и их защите»: массовые письма/звонки и запись разговоров — только после проверки с юристом.

## 2. Объём работ по этапам

| Этап | Что | Статус |
|---|---|---|
| 0 | Починить Mistral-ключ (401), primary → рабочая flash-модель | Блокер, backend |
| 1 | Поиск товаров/компаний (Tavily + Browser Use) по требованиям лота | Частично есть (`product_search`, `/api/products/search`) |
| 2 | Сверка по пунктам ТЗ + шорт-лист с объяснением | Новое, backend + frontend |
| 3 | Черновики писем + план звонка, очередь approval | Новое |
| 4 | Отправка писем после одобрения (OAuth ящика компании) | Новое |
| 5 | Звонки через Leximo после одобрения | Новое, после юриста |
| 6 | Ограниченная автономность (белый список, лимиты) | Только после статистики этапов 3–5 |

## 3. Функциональные требования

### F1. Поиск поставщиков (этап 1)
- Вход: `lot_id` + извлечённые требования (из Documenter).
- Агент строит 3–7 поисковых запросов (товар + синонимы + характеристики) → Tavily.
- Для топ-кандидатов: заход на сайт через Browser Use, извлечение карточки: название, поставщик, цена, наличие, город, срок доставки, телефон, email, сертификаты/гарантия (или пометка «нет данных»).
- Выход: сырой список ≤20 кандидатов с источниками (URL каждой характеристики).

### F2. Сверка по пунктам ТЗ (этап 2)
- По каждому пункту спецификации статус: `подходит / частично / не подходит / нет данных` + ссылка-источник.
- Общий score (0–100) — вторичен, объяснение первично.
- Предупреждения: нет сертификата, неизвестна гарантия, цена без доставки, посредник (не производитель).

### F3. Шорт-лист и approval (этапы 2–3)
- Карточка поставщика: фото, цена, наличие, город, срок, % соответствия, подтверждённые/ненайденные параметры, контакты, предупреждения.
- Действия пользователя: одобрить / отклонить / «показать черновик письма» / «показать план звонка».
- Без одобрения — никаких исходящих контактов (архитектурный запрет, см. F6).

### F4. Письма (этап 4)
- Отправка **от лица компании пользователя**: подключение ящика по OAuth (минимальные scope, отзыв в 1 клик) либо отправка с домена Tendr «от имени».
- Три режима на поставщика: `review` (показать черновик → отправить), `trusted` (авто, но дневной лимит + стоп-слова), `manual` (только черновик).
- Черновик подставляет рабочие контакты пользователя из профиля (email/телефон).
- Лог каждого письма: текст, время, статус доставки/ответа.

### F5. Звонки через Leximo (этап 5)
- Только после одобрения плана разговора (цель, 3–5 вопросов, красные линии, сценарий выхода).
- Backend → задание в Leximo (MCP) → статус + расшифровка → карточка поставщика.
- Ограничения (код, не промпт): утверждённый сценарий, лимит звонков/бюджета, только рабочее время KZ, стоп-лист, остановка по просьбе, запрет коммерческих обязательств агентом.
- AI представляется, называет компанию и цель звонка.
- Номер покупать не нужно: звонки идут с инфраструктуры Leximo (проверить наличие KZ caller ID до интеграции).

### F6. Политика торга (кодируется состояниями, не промптом)
- Цена в допуске ±X% (задаёт пользователь) → дальше.
- Выше допуска, в пределах Y% → **одна** встречная попытка по скрипту → стоп.
- Выше Y% → вежливый отказ без обязательств.
- У агента **нет** инструментов «согласиться», «заключить», «оплатить» — их отсутствие в toolset, а не запрет в тексте.

### F7. Персонализация пользователя
- Системный промпт собирается из: шаблона + профиля компании + рабочих контактов (только для исходящих) + белого/стоп-листов.
- Хранение: таблицы `company_profiles`, `supplier_allowlist`, `supplier_blocklist` (см. §6).
- Контакты никогда не уходят в логи сторонних сервисов.

### F8. Персонализация тендеров («подобрано для вас»)
- Сигналы: профиль (категории, регионы, бюджетная вилка) + поведение (открытия, анализы, сохранения, одобрения/отказы) + исходы.
- Cold start: онбординг-квиз (3–5 вопросов) при регистрации.
- Скоринг v1 (без ML): взвешенная сумма — категория, регион, бюджет, знакомый заказчик, свежесть, срочность; считается поверх существующего поиска лотов.
- Скоринг v2: перевзвешивание по истории одобрений; collaborative — позже.
- Каждая рекомендация — с объяснением «почему» (3 буллета), а не голым процентом.
- Доставка: блок в кабинете + дайджест в Telegram-бота (лимит N/день, настройка).
- Кнопки «подходит / не подходит» на карточке — топливо для v2, с первого дня.

### F9. Тарифы и кредиты
- Plus: поиск компаний/товаров. Pro: + глубокая сверка и черновики. Ultra: + письма, звонки, расшифровки.
- Browser-минуты и звонки считаются отдельно от LLM-кредитов.
- Правило маржи: себестоимость пула ≤ 25–30% цены тарифа.

### F10. Аудит
- Лог: поиски, сверки, черновики, одобрения/отказы, письма (текст+статус), звонки (план, запись, расшифровка), расходы по каждому действию.

## 4. Нефункциональные требования
- Безопасность: секреты только на backend; OAuth с минимальными scope; отзыв доступа в 1 клик.
- ПДн РК: массовые рассылки, звонки, записи разговоров — после заключения юриста. До этого — только ручные черновики.
- Лимиты: дневные/бюджетные на письма и звонки; стоп-лист; только рабочее время KZ.
- Наблюдаемость: расходы (токены, Tavily, browser-минуты, звонки) пишутся на каждое действие.

## 5. Архитектура

```
Тендер → Documenter (требования)
  → SupplierAgent (backend-оркестратор: правила, лимиты, approval, история)
      → Tavily (поиск) + Browser Use (чтение сайтов) — «руки и глаза»
      → LLM (сверка, черновики, планы звонков)
  → Шорт-лист → Approval UI → Email (OAuth) / Leximo (MCP)
```

- OpenClaw — только локальные эксперименты со сценариями, не прод (иначе два браузерных стека и двойные расходы).
- TimesFM — не использовать (прогноз рядов ≠ рекомендации).
- MiroFish — не использовать (соцсимуляции ≠ матчинг; дорого; AGPL-3.0 с копилефтом опасен для SaaS).

## 6. Данные (новые таблицы)

- `company_profiles` (user_id, категории, регионы, бюджетная вилка, мощности, рабочие email/телефон)
- `supplier_allowlist` / `supplier_blocklist` (user_id, supplier, причина)
- `supplier_candidates` (lot_id, supplier, карточка, score по пунктам, источники)
- `approval_queue` (candidate_id, тип: email/call, черновик/план, статус, решение пользователя)
- `outreach_jobs` (тип, текст/сценарий, статус, стоимость, расшифровка)
- `price_policies` (user_id, допуск X%, предел Y%, скрипт встречной)
- `user_interests` (категории, регионы, мин. чек — из квиза и поведения)
- `tender_feedback` (user_id, lot_id, подходит/нет)
- `digest_settings` (каналы, лимит в день, время)

## 7. API (новые эндпоинты, префикс /api)

- `POST /api/suppliers/search` {lot_id} → запуск поиска
- `GET /api/suppliers/shortlist?lot_id=` → шорт-лист со сверкой
- `POST /api/suppliers/feedback` {supplier_id, подходит/нет}
- `POST /api/approvals` {candidate_id, тип, решение, текст/план} + `GET /api/approvals/pending`
- `POST /api/outreach/email` и `/api/outreach/call` (только из approval, с проверкой)
- `GET /api/outreach/{job_id}` (статус, расшифровка)
- `GET/PATCH /api/profile/interests`, `POST /api/tenders/feedback`, `GET/PATCH /api/digest/settings`
- Формат ошибок — существующие стабильные коды (`QUOTA_EXCEEDED` и др.), сырой detail наружу запрещён (фронтенд-правило уже действует).

## 8. Модели и провайдер

Провайдер: **Novita** (полный каталог + sandbox) или **Fireworks** — один, по аптайму; OpenAI-совместимый API, `OpenAICompatProvider` без переписывания. Цены проверены 2026 (перепроверять ежеквартально):

| Роль | Модель | Цена вх/вых за 1M |
|---|---|---|
| Разбор документов (primary) | GLM-5.3-Flash | $0.15 / $0.50 |
| Сверка требований | DeepSeek V4 Flash | $0.14 / $0.28 |
| Fallback | Qwen3.8 Flash | $0.09 / $0.28 |
| Второе мнение (спорные) | GLM-5.3 / DeepSeek V4 Pro | $1.3–1.4 / $3.9–4.4 |
| Не брать | Kimi K3 ($3/$15), полный Mistral-large как primary | — |

Себестоимость анализа (50K вх + 4K вых): GLM-Flash ≈ $0.010, DeepSeek Flash ≈ $0.008. Пул Plus (150) ≈ $1.5 при цене ~$20 — маржа здоровая.

## 9. Конкурентный ответ (ETS-Тендер)

ETS — площадка сделок (B2B, тарифы, ЭЦП, аналитика), Tendr — слой победы. Не копировать: их data moat (история ставок, win rate рынка), свою площадку торгов. Усиливать: объяснимую сверку по ТЗ, win rate пользователя по его анализам, пакет документов под ключ, мультиплатформенность (включая поставщиков ETS), партнёрство как встраиваемый AI-слой.

## 10. Критерии приёмки

- Поиск по лоту возвращает ≤20 кандидатов с источниками и контактами (где есть).
- Каждый кандидат — статусы по пунктам ТЗ, не только общий %.
- Без approval — ноль исходящих (проверяется тестом: ни писем, ни звонков).
- Режимы review/trusted/manual работают; trusted ограничен лимитом.
- Политика торга: превышение Y% → отказ без обязательств (тест).
- Подборка тендеров с объяснением «почему», cold start через квиз, дайджест в бота с лимитом.
- Расходы пишутся на каждое действие; пул тарифа ≤ 30% цены.
- Юрист подписал рассылки/звонки/записи до этапов 4–5.

## 11. Риски

- Ключи LLM (сейчас 401 на Mistral) — держать 2 рабочих провайдера.
- Цены моделей меняются — перепроверка ежеквартально + алерты на расход.
- Юридические (ПДн, запись звонков) — этапы 4–5 не стартуют без заключения.
- AGPL-зависимости запрещены; OpenClaw — только локально.
- Злоупотребление trusted-режимом — лимиты и стоп-слова обязательны с первого дня.
